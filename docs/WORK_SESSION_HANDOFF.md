# KudaVPN — текущая передача состояния

Обновлено 20 октября 2026 года. Этот документ описывает **изолированный тестовый контур** на уже оплаченном JustHost и дополняет прежний handoff в других ветках. Он не является разрешением на production-развёртывание или массовую выдачу.

## Что работает сейчас

- Draft [PR №7](https://github.com/Denis-hud-dev/vpn-service/pull/7) (`codex/telegram-pilot-trial`) опирается на draft PR №6 и №5; PR не объединены. Изменения этой ветки в production DigitalOcean не попадали.
- На JustHost отдельно запущены `kudavpn-pilot-two-node.service` (Xray VLESS + TCP + REALITY + Vision, TCP/10443, отдельные ключи, конфигурация и процесс), `kudavpn-telegram-pilot-feed.service` (HTTPS TCP/18443) и `kudavpn-telegram-pilot-bot.service` (`@KudaVPN_Test_Bot`). Управляющий mTLS API нового узла слушает только loopback; отдельный Xray API тоже на loopback. На новом узле нет постоянных статических клиентов, максимум один управляемый пользователь.
- Действующие `xray.service` (443), `kudavpn-xray-alt8443.service` (8443) и `kudavpn-pilot-node.service` (9443) при последней проверке были активны и прослушивали свои порты. Их конфигурации не менялись. Службу прежнего контроллера 9443, ранее остановившуюся по тайм-ауту, не запускали.
- Тестовая PostgreSQL 16 на JustHost содержит отдельную БД `kudavpn_telegram_pilot` и отдельную роль. Перенесена только локальная БД тестового бота с одним зарегистрированным владельцем; миграции доведены до head. Перед активацией 24-часового теста в ней было **0 подписок, 0 платежей**, один зарегистрированный узел 10443. Рабочая PostgreSQL DigitalOcean не использовалась.
- Локальный экземпляр `kudavpn-telegram-pilot-bot-1` на Mac остановлен перед запуском того же тестового бота на JustHost, чтобы не было двух Telegram polling. Локальная тестовая PostgreSQL на Mac оставлена как резервная копия; production-контейнеры не трогали. Тестовый бот на JustHost отвечает на локальную проверку готовности и сообщил через Telegram API свою тестовую идентичность.
- Для выданного JustHost имени `r1276248.s2578.vm.mydomain.zone` получен доверенный сертификат Let's Encrypt после успешной staging-проверки. Срок сертификата до 18 января 2027 года. Настроен hook автоматического обновления **только** копии сертификата тестового HTTPS-feed. Внешний запрос к `https://r1276248.s2578.vm.mydomain.zone:18443/s/invalid` подтвердил доверенный TLS и отказ `404`; этот адрес не содержит персонального токена.
- Проверка mTLS нового агента: одноразовый UUID был выдан на 10443 и отозван, агент после этого остался здоровым. Этот UUID не принадлежал владельцу и не публиковался. Ни существующий 9443 UUID, ни его доступ не менялись.
- В тестовом боте добавлена кнопка «Бесплатный тест — 24 часа» в личном кабинете **только** для Telegram ID владельца. Повторное нажатие идемпотентно: не продлевает 24 часа и не создаёт платёж. Активация в групповом/inline чате запрещена; персональная ссылка выдаётся только в личном чате. **20 октября владелец сообщил, что активировал бесплатный тест, импортировал личную HTTPS-подписку в Happ на Android и смотрел YouTube через VPN.** Это реальное подтверждение одного клиентского маршрута; время истечения и состояние БД после активации здесь заново не проверялись.
- Локальная проверка кода после последнего изменения: **132 passed, 6 skipped**. Пропущенные проверки не считать успешными. Доверенный TLS, внешний доступ к 18443, изолированная БД, локальная готовность бота и mTLS агента проверены дополнительно вживую.

## Что пока не доказано

- Владелец подтвердил импорт персональной подписки в Happ и работу YouTube через новый тестовый путь из России. Не проверены все сайты, длительная стабильность на разных сетях и автоматический отзыв после истечения реальных 24 часов.
- Реальных платежей YooKassa не было; платёжная кнопка тестового бота остаётся отключённой. Коммерческий запуск, backup/restore production, массовая нагрузка и мониторинг нескольких узлов остаются вне пилота.
- [GitHub CI для коммита `340dbf9`](https://github.com/Denis-hud-dev/vpn-service/actions/runs/39446582479) завершился успешно. Тестовый код ещё не объединён ни с PR №6, ни с production.

## Как продолжить

1. Не повторять успешный Android-тест без новой гипотезы. При следующей безопасной проверке без раскрытия токена сверить отдельную БД, аренду агента 10443 и корректное истечение/отзыв после фактического окончания срока. Ничего не продлевать автоматически сверх 24 часов.
2. Использовать [аудит основного бота](MAIN_BOT_PRODUCT_AUDIT_2026-10-20.md) для подготовки фирменной страницы подключения и будущего платного цикла в отдельной ветке. Не переносить пилотный UUID/секреты/базу в production.
3. При необходимости отката теперь **сначала** подтвердить отзыв тестового UUID и сохранить состояние тестовой БД. Затем остановить и отключить только `kudavpn-telegram-pilot-bot.service`, `kudavpn-telegram-pilot-feed.service`, `kudavpn-pilot-two-node.service`; при необходимости вернуть локальный `kudavpn-telegram-pilot-bot-1`. Не останавливать 443/8443/9443 и не удалять базу/закрытые резервные копии.

## Секреты и границы

Токен BotFather, пароль тестовой БД, ключ Happ-ссылок, UUID, mTLS-материалы и приватные REALITY/TLS-ключи находятся только в приватных файлах вне Git с ограниченными правами. Этот handoff не содержит их значений или персональных ссылок. Не менять DigitalOcean, рабочие VPN 443/8443/9443, YooKassa, production-бота, production-БД, firewall или общие маршруты. Не объединять PR и не покупать услуги без отдельного решения владельца.

# YooKassa: изолированный тест оплаты

Эта ветка продолжает draft PR №8 и **не развёрнута**. Она повторно использует заказ из PR №5, подписку и отзыв доступа из PR №6, тестовый бот и HTTPS-подписку из PR №7–8. Production-бот и магазин не получают новых функций без отдельного развёртывания.

## Поведение

Только владелец `@KudaVPN_Test_Bot` в личном чате видит кнопку создания **тестового** заказа для 299/799/2490 ₽. Повторное нажатие в течение 30 минут использует тот же заказ и ключ идемпотентности. Сервер каждые 30 секунд читает ожидающие платежи через аутентифицированный `GET /v3/payments/{id}`. Доступ выдаётся только после статуса `succeeded`, `paid=true`, признака `test=true` и точного совпадения идентификатора заказа, суммы и валюты. Неоконченный или отменённый платёж доступ не выдаёт. Повторное подтверждение не продлевает подписку второй раз; новая оплаченная покупка добавляет календарные месяцы к оставшемуся сроку. Уже существующий Happ URL и UUID сохраняются; текущая служба истечения и сверка с агентом отключают доступ после срока.

Здесь нет входящего webhook: опрос провайдера устраняет необходимость менять публичный HTTPS-сервис и не доверяет браузерному возврату. Если провайдер недоступен, платёж остаётся ожидающим, доступ не выдаётся, опрос повторяется; в журнал попадает только тип ошибки, без ID платежа, учётных данных и личной ссылки. Пробный 24-часовой доступ не меняется.

## Включение только после согласованного теста

Нужны **ID и секретный ключ отдельного тестового магазина** YooKassa. Владелец запускает в интерактивном Mac Terminal `python3 scripts/save_yookassa_test_keys.py --shop-id <ID_ТЕСТОВОГО_МАГАЗИНА>`: скрипт спрашивает только секретный ключ через скрытый ввод, не принимает его в аргументе и отказывается работать без терминала. Файлы создаются вне Git в `~/Documents/KudaVPN-private/telegram-pilot/` с правами `0600`, каталог имеет права `0700`; существующие файлы не перезаписываются. Скрипт сохранения не делает запросов к магазину. Не подставлять боевые ключи. Затем `python3 scripts/check_yookassa_test_auth.py --shop-id <ID_ТЕСТОВОГО_МАГАЗИНА>` выполняет ровно один read-only `GET /v3/payments?limit=1` к официальному API с проверкой TLS и сообщает только «Успешно» или «Ошибка», без тела ответа и ключа. Успех подтверждает авторизацию указанной пары реквизитов, но не создаёт платёж и сам по себе не доказывает доступность СБП. Тестовый контур должен передать пути через `PILOT_YOOKASSA_TEST_SHOP_ID_FILE` и `PILOT_YOOKASSA_TEST_SECRET_FILE`, затем явно выставить `PILOT_TEST_PAYMENTS_ENABLED=1` и `PILOT_PAYMENT_RETURN_URL=https://t.me/KudaVPN_Test_Bot`. Флаг требует маркер изолированного пилота, Telegram ID владельца, существующие HTTPS/Happ-параметры и БД `kudavpn_telegram_pilot`; при запуске дополнительно сверяется имя тестового бота. По умолчанию флаг выключен. Перед включением сделать резервную копию **только** тестовой БД и зафиксировать прежний конфиг службы; откат — убрать флаг и перезапустить только тестового бота. Xray и HTTPS-feed менять не требуется.

Для первого end-to-end теста: выбрать тариф в тестовом боте, открыть выданную страницу тестовой оплаты, использовать только способ/данные тестового магазина, дождаться успешного статуса и проверить личный кабинет и старую Happ-ссылку. Затем повторить callback, проверить отсутствие второго начисления, оплатить другой тестовый заказ для продления, имитировать истечение в отдельной БД и проверить отказ на узле. **До появления тестовых ключей проверена только имитация API; настоящий запрос к YooKassa не выполнялся.** Никаких реальных списаний или автоматических платежей.

По [официальной справке YooKassa](https://yookassa.ru/developers/payment-acceptance/testing-and-going-live/testing) тестовый магазин отдельный и тестовые платежи не списывают деньги. СБП в тестовом магазине не проверяется; наличие СБП для конкретного боевого магазина нужно установить отдельно. API использует [Basic Auth и Idempotence-Key](https://yookassa.ru/developers/using-api/interaction-format), а подтверждение следует проверять [по независимому чтению платежа](https://yookassa.ru/developers/using-api/webhooks). Для реального запуска отдельно проверить фискальные чеки и настройки магазина; эта ветка их не включает.

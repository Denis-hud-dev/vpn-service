# Изолированный 24-часовой пробный доступ

Статус: реализация и автоматические тесты в `codex/telegram-pilot-trial`.
Работающий `@KudaVPN_Test_Bot` пока запущен со старым образом; этот код не
развёрнут. Пробный срок **не запущен**, ссылка Happ не создана. Продажи и
YooKassa не используются.

## Границы

- Операторская команда `trial-grant` использует только выделенную БД
  `kudavpn_telegram_pilot`, проверяет пилотный маркер и один заранее
  закреплённый `PILOT_TRIAL_OWNER_ID`. Команды в Telegram для активации нет.
- Начальный срок — ровно 24 часа с первой активации. Повтор `trial-grant`
  не сдвигает истечение. Операция не создаёт строку оплаты или платёжного
  провайдера. В истории есть отдельная запись `pilot_trial_grant`.
- `trial-extend` принимает абсолютное время окончания (рекомендуется UTC),
  не больше семи дней вперёд. Повтор с тем же временем не продлевает второй
  раз. Заблокированную подписку продлевать нельзя. Личное имя профиля,
  HTTPS-ссылка и узловой UUID при продлении сохраняются.
- Лишь бот и feed с пилотным маркером и тем же ID владельца признают
  пробное право. Feed и reconciler ограничены новым портом TCP/10443;
  действующие 443/8443/9443 не выбираются. По умолчанию этот путь выключен.
- Само наличие подписки в БД не даёт VPN-доступа: reconciler должен получить
  подтверждение от отдельного агента, а health должен быть свежим. При
  истечении feed отказывает сразу; бот отмечает срок в пределах минуты,
  узловая краткая аренда прекращает доступ даже при потере связи с агентом.
  Для пилота нужно дополнительно подтвердить разрыв текущего туннеля на
  новом агенте реальным тестом.

## До активации

1. Подтвердить в изолированной БД Telegram ID владельца, уже
   зарегистрированного через `/start`, и записать его только в приватный
   `pilot.env`; там же уже хранится путь к токену тестового бота.
2. После отдельного разрешения установить **новый** Xray и агент на
   JustHost:10443 из шаблонов `deploy/pilot-second/`. Не использовать UUID,
   ключи, агент и конфигурации 9443. Проверить свободный порт, firewall,
   резервирование ресурсов, откат и неизменность 8443/9443.
3. Создать доверенный HTTPS endpoint для `/s/<token>` с выданным JustHost
   FQDN, только после проверки стабильного DNS, сертификата и его продления.
   Ingress не должен занимать действующий TCP/443; по возможности выделить
   порт, уже предусмотренный в пилотном шаблоне. Токены нельзя писать в
   access logs. Feed подключить к **новому** агенту через mTLS и SSH-туннель.
4. В отдельной БД должен быть ровно один новый узел TCP/10443, а его health
   и mTLS preflight должны пройти. Затем обновить только контейнеры
   тестового бота и пилотного feed с этой веткой. Production не трогать.
5. Только после этого один раз выполнить `trial-grant` в контейнере
   изолированного контура. Оператор не должен печатать ID, UUID или ссылку.

Владелец открывает личное меню подключения в `@KudaVPN_Test_Bot`, копирует
персональную HTTPS-ссылку и добавляет её в Happ Android как подписку по URL.
Далее проверяются HTTPS и YouTube, затем намеренно короткое истечение на
**отдельном** пользователе и восстановление через `trial-extend` с прежней
ссылкой и UUID. Параметры ссылок и ключи не сохраняются в Git или отчёте.

До готовности узла и HTTPS URL импортировать в Happ нечего. Запускать
24-часовой таймер заранее нельзя.

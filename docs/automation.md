# Автоматическая проверка KudaVPN

Первый этап запускает GitHub Actions для pull request, push в `main` и в ветки
`codex/**`, а также вручную. Временный runner использует Python 3.12 и
одноразовую PostgreSQL 16. Он проверяет отслеживаемые Git-файлы, зависимости,
синтаксис, offline smoke test, Alembic-миграции и тесты. Итог виден в Actions,
короткий отчёт — в Summary, JUnit XML хранится семь дней как артефакт.

В workflow нет Telegram polling, YooKassa, VPN-клиента, SSH, deployment и
доступа к DigitalOcean. `GITHUB_TOKEN` имеет только `contents: read`; checkout
не сохраняет учётные данные. Тестовая БД создаётся на runner и не содержит
пользовательских данных. Статическая проверка `check_repo_hygiene.py` выявляет
очевидные секреты и резервные копии в отслеживаемых файлах, но не заменяет
проверку diff перед публикацией и GitHub secret scanning.

При красном CI откройте упавший job, Summary и `pytest-results`. Воспроизведите
локально через `python -m pytest -q` без переменных production; PostgreSQL-тест
нуждается в отдельной пустой базе через `TEST_DATABASE_URL`. Исправления делайте
в рабочей ветке и повторно запускайте CI. Codex может анализировать конкретный
провал и готовить исправление в отдельной ветке; этот этап не даёт ему права
автоматически менять `main`, production или оплачиваемую инфраструктуру.

В Codex создана активная задача «KudaVPN CI: диагностика и исправления».
Каждые четыре часа она сверяет новые run и PR для `codex/ci-foundation`.
При подтверждённом сбое она готовит минимальное исправление в отдельной ветке
`codex/ci-fix-*`, запускает локальные проверки, публикует черновой PR в
`codex/ci-foundation` и сверяет повторный CI. При успешных и неизменных run
уведомление не отправляется. Задача не объединяет PR и не имеет разрешения
менять production. Если причина не доказана или публикация недоступна, она
сообщает о препятствии вместо случайного исправления.

Задача использует локальный проект, поэтому для её фоновой работы MacBook и
приложение ChatGPT должны быть включены. Подключение GitHub допускает чтение,
но операции записи через него возвращают 403; для публикации доступны уже
авторизованные GitHub Desktop и Safari с разрешением Computer Use. Первые
несколько запусков нужно проверить: успешное создание исправляющего PR пока
не подтверждено реальным падением CI.

Ветка `codex/integrated-ci-foundation` объединяет проверки с экспериментальной
логикой подписок, Happ и управления Xray. Обычный CI выполняет тесты этой
логики, но реальный тест с локальным бинарником Xray пропускается без
`TEST_XRAY_BINARY`. Такой тест запускается отдельно на доверенном локальном
бинарнике, чтобы CI не загружал произвольный исполняемый файл во время сборки.
Ни один тест не использует production-базу или действующий VPN-узел.

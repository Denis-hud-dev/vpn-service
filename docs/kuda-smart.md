# Kuda Smart — изолированный прототип

## Что работает сейчас

- HTTPS-подписка KudaVPN выдаёт только личные VLESS/REALITY-конфигурации с подтверждённым доступом и свежим состоянием узла. Нездоровые узлы исключаются сервером; это проверка со стороны KudaVPN, а не измерение пути с телефона.
- Happ позволяет импортировать обычную HTTPS-подписку и вручную проверять задержку узлов. В тестовом боте есть информационный экран Kuda Smart. Он не переключает VPN и не меняет действующую подписку.
- В отдельном модуле подготовлен **не подключённый к живому API** пример HTTP-заголовков для выбора минимальной задержки при запуске Happ. Он требует Provider ID и минимум два независимых здоровых узла.

## Подтверждённые возможности Happ

- [Официальное руководство по ping](https://www.happ.su/main/faq/ping): измерение задержки для всей подписки и отдельных конфигураций; «Ping on Launch»; проверка через proxy измеряет полный путь. Ping — не пропускная способность.
- [Официальное управление приложением](https://www.happ.su/main/dev-docs/app-management): параметры `subscription-autoconnect: 1` и `subscription-autoconnect-type: lowestdelay` выбирают сервер **при запуске приложения**. `subscription-ping-onopen-enabled: 1` запускает проверку списка при открытии. Для этой группы параметров нужен Provider ID.
- [Provider ID](https://www.happ.su/main/dev-docs/provider-id): регистрация у Happ; приложение ежедневно отправляет провайдеру идентификатор, хэш домена подписки, HWID устройства и сведения об ОС. Использование требует отдельного решения по приватности и проверки условий.

Нет подтверждения, что Happ автоматически разрывает и восстанавливает уже работающий туннель на другом узле при потере соединения. Автоподключение при запуске не является доказательством failover. Поведение на Android и iOS нужно проверять отдельно.

## Безопасная архитектура

1. Control plane продолжает выдавать каждому клиенту только его конфигурации на узлах, где доступ реально применён и здоровье подтверждено. Доступ и истечение срока продолжают исполняться на каждом узле независимо.
2. После появления второго независимого управляемого узла и проверки изоляции добавить в отдельную тестовую подписку оба узла. Не смешивать пользовательские UUID и не выдавать общий ключ. Для геовыбора хранить подтверждённую страну узла, а не выводить её из IP по догадке.
3. На устройстве сравнить ping **через proxy** и реальный HTTPS-трафик на обеих сетях. Проверить выбор `lowestdelay` при старте, затем отдельно воспроизвести отказ активного узла и измерить время восстановления. Не заявлять failover без этого теста.
4. Серверный health-монитор защищает будущие обновления подписки, но уже импортированный клиент может сохранять старый список до обновления. Поэтому это не замена клиентскому переключению.
5. Режим «Максимальная скорость» требует измерения пропускной способности, ограничений нагрузки и механизма выбора; ping не подходит. Режим «Выбрать страну» требует проверенных узлов в разных странах. Пока оба отображаются только текстом как будущие возможности.

## Условия включения

Нужны отдельное согласование передачи данных Happ через Provider ID, второй независимый узел, разрешение на изолированное тестирование Android/iOS, подтверждение поведения при обрыве и метрики без секретов. До этого не добавлять заголовки прототипа в `/s/{token}`, не показывать режимы как рабочие и не изменять Xray или production-бота.

## Проверка интерфейса перед тестовым развёртыванием (23 октября 2026)

- Экран представляет собой короткое Telegram HTML-сообщение с двумя действиями: «Подключить VPN» и «Назад». Режимы Smart, скорости и страны описаны как будущие; кнопок их включения нет. Из «Назад» пользователь возвращается в главное меню, а из подключения — к существующему пути Happ.
- Автоматические проверки проходят последовательность меню → Kuda Smart → назад → Kuda Smart → подключение → инструкция Happ → меню, проверяют одно подтверждение нажатия и редактирование одного сообщения без дублей. Отдельно проверяются вариант с фирменными Telegram emoji и текстовый запасной вариант, компактность текста/кнопок для мобильного Telegram и скрытие экрана при выключенном флаге пилота.
- Android и iOS получают одинаковый текст и inline-кнопки Telegram. Проверка формата и длины выполнена локально; фактическая отрисовка на физических телефонах и нажатия в `@KudaVPN_Test_Bot` ещё не проверены. Это приёмочная проверка после разрешённого развёртывания только в изолированном боте.
- Прототип выбора сервера не подключён к живой HTTPS-подписке. Отображение этого экрана не меняет активное VPN-подключение, тариф, личную ссылку или серверную конфигурацию.

Он убирает только новый `50-kuda-smart.conf` и возвращает прежний рабочий каталог тестового бота. Синтаксис сценария проверен, выполнять его без причины не нужно.

Проверены меню Kuda Smart, «Назад», главное меню и переход к прежнему экрану подключения в автономном Telegram-harness на новом каталоге. Физическую отрисовку на Android/iOS владелец проверяет в `@KudaVPN_Test_Bot` после `/start` → «Kuda Smart · скоро»; включать новый VPN-режим для этого не нужно.

# JustHost 9443: ограниченный пилот, 18 октября 2026

Письменное разрешение JustHost подтверждено в заявке №986998 (ответ от
17 октября 2026): публичный платный VPN, персональный доступ и
Xray/VLESS/REALITY/Vision допустимы. Отдельного тарифа или согласования не
потребовали. Действуют ограничения тарифа по скорости и общие правила против
злоупотреблений; при жалобах провайдер может ограничить сеть. Это разрешение
не доказывает доступность подключения из каждой российской сети.

На уже оплаченном VPS создан **отдельный** агент и Xray-процесс для одного
тестового UUID. Его вход слушает TCP/9443, Xray API — только 127.0.0.1:19085,
управляющий mTLS API — только 127.0.0.1:19443. Конфигурация использует VLESS,
TCP, REALITY и Vision с новым набором ключей; список статических клиентов
пуст. Управляющий контроллер продлевает короткую аренду только тестового UUID.
Его служба остановится через 24 часа после запуска и не перезапустится сама;
при потере продления агент удалит UUID после окончания аренды. Для следующего
сеанса пилота нужно отдельно проверить состояние и снова запустить контроллер.

Проверки: Xray и агент активны; mTLS health сообщает `healthy: true`; в
управляемом Xray ровно один клиент. На Mac через локальный Xray/SOCKS два
запроса через новый вход получили HTTP 200 (`https://example.com/` и
`http://1.1.1.1/cdn-cgi/trace`). Это проверка доступного маршрута Mac, а не
доказательство работы из России без другого VPN. На сервере исходящий HTTPS
к example.com также дал 200. Последние журналы пилотных служб без ошибок.

При первой выдаче пользователя обнаружилось, что `ProtectSystem=strict`
запрещает запись временного файла Xray CLI в `/tmp`. Это исправлено **только
в новой службе** указанием `TMPDIR=/var/lib/kudavpn-pilot`; шаблон PR №6 и
тест обновлены. После исправления агент выдал ровно одного клиента и
восстановил его после перезапуска только пилотной службы.

Рабочая служба TCP/8443 не менялась и не перезапускалась: тот же PID,
те же контрольные суммы конфига и unit-файла, порт прослушивается. Повторная
проверка её трафика из Android в рамках пилота не проводилась.

Приватный тестовый URI и QR для Happ находятся только в локальной папке
`KudaVPN-private`, с правами 0600. В Git не добавляются. HTTPS-подписка пока
не готова: отдельного доверенного домена нет. Ручной импорт QR проверяет
передачу данных через новый узел, но не проверяет механизм обновления подписки.

Остаётся: импортировать профиль в Happ на Android через домашний Wi-Fi без
другого VPN; подтвердить реальные HTTPS-сайты и YouTube. Только после
подтверждения проверять блокировку, разрыв уже открытого туннеля,
восстановление, продление и естественное истечение. При любой угрозе
работающему 8443 останавливать **только** новые пилотные службы. Production
DigitalOcean, бот, платежи и рабочая база не менялись.

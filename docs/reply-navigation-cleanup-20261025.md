# Очистка нажатий нижней клавиатуры

Ветка `codex/reply-navigation-cleanup-20261025` поверх Draft PR №24. Причина накопления: Telegram присылает нажатия ReplyKeyboard как обычные текстовые Message, а три обработчика раньше только открывали новый экран бота.

Добавлен единый `remove_reply_command`: только при включённом изолированном pilot_welcome, в private-чате, если chat.id совпадает с from_user.id, отправитель не бот, текст точно равен одной из трёх констант клавиатуры. Пересланные сообщения, sender_chat и via_bot исключены. Вызов deleteMessage нацеливается исключительно на chat.id/message_id входящего сообщения; чужой ID или диапазон истории не используется. Telegram не отличает нажатие от вручную отправленного идентичного текста: точные названия трёх кнопок считаются навигационными командами.

Удаление выполняется перед открытием раздела, с тайм-аутом 3 секунды. TelegramAPIError/TimeoutError оставляют сообщение и не прерывают навигацию. В журнал попадает только класс ошибки без текста сообщения, идентификаторов и личных ссылок. Изменения не касаются /start и обычного текста, отправки клавиатуры, подписок или платежей.

Предыдущий экран бота по-прежнему удаляется только по сохранённому навигационному ID, после отправки и сохранения нового экрана. При отказе удаления остаётся существующий безопасный fallback. Баннер, подтверждения оплаты, события подписки, сообщения поддержки, обычный текст и другие чаты сохраняются. Уже существующую историю не сканируем и не очищаем.

## Проверки

80 профильных тестов прошли: три кнопки, точные ID удаления, отказ удаления и дальнейшая навигация, тайм-аут, повторные нажатия, сохранение баннера/уведомлений/обычного текста, запрет чужого чата/группы/бота/пересылки, выключенный pilot и навигация после перезапуска с постоянным хранилищем. Тест ошибки отправки нового экрана сохраняет проверку прежнего навигационного ID; удаление входящей команды теперь ожидаемо.

# Ограниченная приёмка управляемого VPN-узла KudaVPN

Документ описывает **будущее** испытание после отдельного разрешения владельца.
Код PR №6 не установлен на JustHost или DigitalOcean. Работающий статический
JustHost TCP/8443 и DigitalOcean TCP/443 не используются управляющим агентом.

## Что запускается отдельно

- Новый Xray-процесс с одним VLESS + TCP + REALITY + Vision inbound на заранее
  проверенном **свободном** порту. В конфигурации `settings.clients: []`, нет
  статических пользователей и нет fallback. Новый REALITY private key и
  сертификаты управления хранятся вне Git. Нельзя копировать тестовый UUID с
  рабочего 8443. `XRAY_CONFIG` доступен только отдельному сервисному пользователю
  (`0600`); `XRAY_API_ADDRESS` — только `127.0.0.1`.
- Агент запускает этот Xray дочерним процессом в **той же** службе systemd.
  Пример unit для ревью (пути и интерфейс определить на площадке):

  ```ini
  [Unit]
  Description=KudaVPN isolated managed node
  After=network-online.target
  Wants=network-online.target

  [Service]
  Type=simple
  User=kudavpn-node
  Group=kudavpn-node
  WorkingDirectory=/opt/kudavpn-node
  EnvironmentFile=/etc/kudavpn-node/agent.env
  ExecStart=/opt/kudavpn-node/venv/bin/python -m bot.node_agent.main
  Restart=on-failure
  RestartSec=3s
  KillMode=control-group
  TimeoutStopSec=10s
  NoNewPrivileges=yes
  ProtectSystem=strict
  ProtectHome=yes
  ReadWritePaths=/var/lib/kudavpn-node

  [Install]
  WantedBy=multi-user.target
  ```

  До запуска проверить `systemd-analyze verify`, расположение бинарника и
  права, затем `xray run -test -c` для **новой** конфигурации. Переменные в
  `/etc/kudavpn-node/agent.env` — только для нового сервиса: `NODE_AGENT_STATE`,
  `XRAY_BINARY`, `XRAY_CONFIG`, `XRAY_API_ADDRESS`, `XRAY_INBOUND_TAG`,
  `XRAY_INBOUND_PORT`, `NODE_AGENT_CERT`, `NODE_AGENT_KEY`,
  `NODE_AGENT_CLIENT_CA`; при необходимости `NODE_AGENT_LISTEN` и
  `NODE_AGENT_PORT`. Файл `0600`, каталог `0700`, отдельный CA и mTLS.
  Ограничить маршрут к порту агента только центральным управляющим сервером;
  порт Xray API наружу не открывать. Не переопределять защищённые порты 443/8443.

## Один тестовый пользователь, без настоящей оплаты

1. Получить отдельное разрешение на установку **только нового** сервиса;
   проверить копию ответа JustHost №986998, действующие порты/правила, сделать
   бэкап нового состояния и записать команды отката. Никаких изменений в
   действующих службах.
2. В изолированной тестовой БД создать одного фиктивного пользователя и
   имитировать подтверждённую оплату. Управляющий сервис выдаёт персональный
   UUID с короткой арендой, затем HTTPS-ссылку Happ. Убедиться, что UUID
   отсутствует в журналах и отличается от рабочего 8443.
3. Импортировать ссылку на Android, проверить через домашний Wi-Fi реальный
   HTTPS/YouTube и внешний IP. Статус «подключено» сам по себе не считается
   успехом. Продлить тестовый срок и убедиться, что ссылка/UUID сохранились,
   а срок аренды на узле обновился.
4. Открыть длинное HTTPS-соединение через тестовый узел. Заблокировать
   **только этого** фиктивного пользователя. Требуемый результат: feed сразу
   отказывает; центральная БД фиксирует намерение отзыва; агент снимает UUID,
   перезапускает лишь свой Xray; открытый поток обрывается; новая попытка
   VLESS не авторизуется; `revocation_confirmed=true` появляется только после
   успешного применения. Сверить PID старого/нового управляемого процесса и
   неизменный PID/состояние рабочего 8443.
5. Повторить отдельно с естественным истечением срока, отзывом ссылки и
   потерей связи с центром: при отключённом центре UUID должен исчезнуть не
   позднее локального TTL 120 секунд плюс цикл сверки 5 секунд. Затем
   восстановить связь и проверить версионное согласование. Убить **только
   новый** агент в испытании: его Xray-процесс и порт должны исчезнуть вместе
   с группой systemd; при рестарте возвращаются лишь неистёкшие аренды.
6. Смоделировать отказ применения отзыва: статус `503`, узел нездоров,
   `revocation_confirmed=false`, повторная попытка после восстановления.
   Настроить оповещения по ошибкам согласования, нездоровому узлу и зависшим
   неподтверждённым отзывам. Без этих проверок платных пользователей не
   переводить.

## Откат

Остановить только новую службу и убедиться, что её Xray-порт закрыт. Не
удалять запись о неподтверждённом отзыве до сверки. Выключить новый узел из
тестовой выдачи, сохранить обезличенные журналы, восстановить лишь файлы и БД
этого узла при необходимости. Рабочий 8443 и управляющий DigitalOcean остаются
без изменений. Перезапуск общего Xray и откат миграции на работающей БД не
входят в этот сценарий.

## Граница готовности

Локальные тесты проверяют версионные аренды, перезапуск дочернего процесса,
удаление/восстановление UUID и отсутствие ACK при ошибке. Они не доказывают
приёмку systemd, сетевую стабильность Happ и фактическое размыкание реального
туннеля на JustHost. До испытания узел и оплата остаются неактивными.

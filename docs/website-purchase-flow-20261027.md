## Сверка при отсутствии webhook

`YooKassaTestClient.list_page` использует документированные GET `/v3/payments` и `/v3/refunds`, UTC `created_at.gte/lte`, limit10 и opaque cursor. Страница ограничена/валидируется; live payment в test-клиенте отклоняется. Refund test/environment доказывается GET его parent. [Списки/пагинация ЮKassa](https://yookassa.ru/developers/using-api/lists).

`ReconciliationJournal` — защищённый retry journal0700/0600, не финансовый ledger и не вторая БД подписок. В нём только тип/ID объекта и parent, checkpoint, attempts/due, фиксированный outcome. Нет API JSON, реквизитов, персональных URLs или UUID VPN. Канонические `Payment`/`SubscriptionHistory` остаются источником учёта денег/срока.

- Фиксированные bounds сохраняются на всех страницах; enqueue и advance cursor — одна SQLite transaction. Падение до commit повторяет страницу; после commit jobs остаются. Каждое tick ограничено pages/jobs. Отдельный файл lease исключает несколько runner; не flock самого SQLite inode (проверена совместимость на Mac).
-15min overlap, задержка обнаружения60s и daily sweep от первого локального заказа покрывают отложенную видимость. Pending jobs не теряются после прохода creation-window. Cursor cycle не пропускается; discovery_retry требует проверки при устойчивом повторении.
- Только известные local order metadata из списка платежей допускают GET. Новый независимый GET проверяет test, ID, immutable order UUID/сумму/валюту перед восстановлением потерянной привязки. Это безопасно и после23h, без POST/confirmation URL/нового idempotency key. Несоответствие → review, не выдача срока.
- Оплаты/возвраты исполняются прежними `PaymentNotificationProcessor`/`TestRefundProcessor`. Crash после canonical commit перед inbox ack повторяется безопасно через existing unique grant. Уже возвращённая покупка повторно не активируется.
- Pending и сетевые ошибки сохраняют retry с backoff; outcomes пишутся при изменении, без полных exception/response. Неопознанный parent возврата сохраняется для повтора. Refund сначала сверяет ещё pending parent, чтобы не возникло выдачи уже возвращённого срока поздним retry.
- Полный возврат последней покупки восстанавливает только доказанный предыдущий оплаченный срок. Частичный/ранний возврат и неоднозначное изменение подписки остаются review. У исходной refund-review SQLite сохраняется операционное назначение; коммерческая отчётность/процедура оператора ещё требуют приёмки.

## Webhook

Опциональный `inbox` в прежнем test handler проверяет local payment/parent, сохраняет IDs перед HTTP200. Body status/paid/amount не передаётся как доказательство. Неизвестный ID не вызывает внешний GET. Ошибка записи даёт503; restart обрабатывает inbox. Старый synchronous handler совместим и тоже независимо проверяет API. [ЮKassa: уведомления](https://yookassa.ru/developers/using-api/webhooks).

На сервере endpoint **не опубликован**. По официальным требованиям нужны HTTPS443/8443; нынешний20443 не подходит, рабочие VPN sockets не меняются. Для интеграционного живого webhook потребуется согласованный ingress; API-сверка может работать без изменения сети и остаётся резервом. Не считать offline HTTP-test доказательством доставки ЮKassa.

## НПД, СБП и Telegram

НПД без НДС уже подтверждён владельцем. `receipt_ledger.tick()` — recoverable hook после обработки/рестарта; он только создаёт/сверяет обязательства. `NPDLedger.record` требует доверенного operator_confirmed=True, фактического document_ref и отдельного `registration_confirmed=True` для issued; delivered требует `delivery_confirmed=True` и ранее зарегистрированный документ. Нет публичной HTTP-операции issued/delivered и автоматической подмены квитанцией ЮKassa. Значения подтверждает будущий доверенный оператор/интеграция, не браузер покупателя. Тесты — только искусственные evidence; настоящих чеков нет.

Согласовать фактическую регистрацию/доставку/исправление чека через «Мой налог» или подтверждённого партнёра. [ЮKassa для самозанятых](https://yookassa.ru/developers/payment-acceptance/receipts/basics) указывает, что автоматическая опция в ЮKassa недоступна. Prototype0009 и canonical0008 не смешивать частичной миграцией. В действующем checkout hook не включён.

Владелец подтвердил поддержку СБП магазином. Sandbox ограничен картой/ЮMoney; СБП там не включается и отсутствие её не ошибка. Перед live остаётся проверка capability конкретного магазина/адаптера и отдельно разрешённая реальная приёмка. Боевые ключи не запрашивались/не подключались.

[Актуальные Telegram Stars FAQ](https://core.telegram.org/bots/payments-stars#faq) требуют Stars для цифровых услуг внутри ботов/Mini Apps независимо от самостоятельного сайта. Рублёвая касса остаётся независимым сайтом; внешних checkout-ссылок в бот не добавлено. Stars prototype/Router выключены, TEST-бот не блокирует сайт.

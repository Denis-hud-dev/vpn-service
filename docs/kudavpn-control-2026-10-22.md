# KudaVPN Control — безопасный первый срез

Статус: **код в отдельной ветке; на JustHost и в тестовом боте не развёрнут**. Основа не создаёт VPN-доступ автоматически и не меняет существующие UUID, ссылки или службы. Новая миграция `0009_control_profiles` добавляет только таблицы; для её применения к изолированной БД и переключения бота нужен отдельный контролируемый релиз с резервной копией.

## Проверенные ограничения

- Действующая персональная HTTPS-подписка выдаёт один UUID из `node_access` на подписку и узел. Один UUID можно импортировать в несколько Happ. Поэтому число физических устройств, их названия, последнюю активность и отдельное отключение по имеющимся данным установить нельзя. Таблица `devices` относится к старому WireGuard-механизму и не должна отображаться как список Happ.
- Агент управляет UUID по mTLS и подтверждает применение. При отзыве он перезапускает **весь отдельный процесс Xray**, чтобы закрыть уже открытые туннели. Это прервёт и других пользователей того же процесса; для индивидуального отключения на общем процессе текущий механизм непригоден.
- Рабочий управляемый Xray сконфигурирован только с `HandlerService`; пользовательские счётчики не включены. Для измерений нужны `StatsService`, `stats` и `policy.levels[0].statsUserUplink/Downlink` в **отдельном** тестовом Xray. Включение требует изменения конфигурации и перезапуска именно этого процесса, что в этой ветке не выполняется. Xray предоставляет счётчики по email, а не аппаратный идентификатор. Источник: [API](https://xtls.github.io/en/config/api.html), [Policy](https://xtls.github.io/en/config/policy.html), [Stats](https://xtls.github.io/config/stats.html).
- Действующий тариф не содержит проверенного числового лимита трафика. До его утверждения интерфейс не должен показывать лимит или процент расхода.

## Что добавлено

- `DeviceProfile`: отдельный UUID для **логического профиля устройства**, название/платформа, явные состояния и nullable `last_seen_at`. Это не доказательство уникальности физического телефона: пользователь может скопировать ссылку. Создание резервирует только `pending`-слот, проверяет владельца, активную подписку, доступный узел и лимит, но не выдаёт ссылку и не касается агента. При наличии старого общего `NodeAccess` создание блокируется до отдельной миграции клиента.
- `ProfileTraffic`: накопленные подтверждённые дельты, последний образец, идентификатор процесса Xray и признак полноты. Первое измерение — базовая точка. Повторные и устаревшие образцы не учитываются, перезапуск/сброс счётчиков делает показатель недоступным до проверки непрерывности. Чужой пользователь не может прочитать показатель. Пока нет реального источника, кабинет продолжает показывать «Нет данных».
- Существующие статусы/сроки/тарифы, продление, Happ-ссылка и тестовая оплата не изменены. Действующие экраны «Устройства» и «Трафик» честно указывают на недоступные измерения.

## До безопасного включения в @KudaVPN_Test_Bot

1. Сохранить закрытую копию изолированной PostgreSQL и файлов тестового бота; проверить сценарий восстановления. Миграцию применять только к тестовой БД, сохранить прежний бинарник и unit для отката.
2. Решить отдельную архитектуру принудительного разрыва **одного** профиля. Варианты: независимый процесс/вход для каждого профиля либо подтверждённый адресный механизм закрытия сессий без перезапуска общего Xray. До этого кнопка «Отключить устройство» запрещена. Проверить на двух тестовых UUID, что отзыв первого не прерывает второй.
3. На изолированном Xray, не занятом действующими пользователями, включить StatsService и пользовательские счётчики; валидировать конфигурацию тестовым бинарником, резервную копию и откат. Добавить строго локальный сбор через защищённого агента; не открывать API наружу. Проверить два независимых профиля, байты по каждому, перезапуск и пропуск выборки. Только после этого показывать трафик и последнюю активность.
4. Сделать отдельные владельцем ограниченные bearer-ссылки/QR для каждого профиля Happ. Переход со старой общей ссылки — отдельная миграция с согласием тестового владельца; старый UUID и тестовый VPN до успешной проверки не отзывать.
5. Проверить Android и Mac: индивидуальный импорт, лимит, чужие callback/ссылки, продление без замены профиля, истечение, отзыв активного туннеля и работа оставшегося пользователя.

**Условие остановки:** если любое изменение требует перезапуска рабочего 443/8443/9443/10443 или может прервать чужой туннель, не развёртывать. Этот срез не меняет ни один сервер.

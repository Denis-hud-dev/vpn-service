# KudaVPN Monitor: подготовка, 26 октября 2026

## Разрешённая задача

Отдельный служебный Telegram-бот: полный отчёт каждые4часа даже без изменений, срочные предупреждения с дедупликацией, команды только владельцу. Работа на серверах независимо от Mac/Codex, автозапуск и журналирование. Не менять приложения, VPN-конфигурации, БД, платежи и размещение DigitalOcean; новых платных ресурсов не создавать.

## Подтверждённые точки проверки

Read-only SSH с ранее доверенными host keys доступен на обоих VPS. На JustHost активны Xray443/8443, пилоты9443/10443, тестовые bot/feed/checkout и PostgreSQL16. Старый `kudavpn-pilot-control.service` уже имеет failed — не объявлять его исправным и не перезапускать в рамках мониторинга.

DigitalOcean: существующий `kudavpn-fra-01`, контейнеры `kudavpn-premium-bot-1`, `kudavpn-premium-postgres-1`, `kudavpn-xray-xray-1` healthy; основной `/ready` на loopback18080 вернул true. Production не изменялся. Это разовые наблюдения, ещё не круглосуточный мониторинг.

## Следующая реализация

План: отдельный read-only collector, актуальные CPU/RAM/диск, состояние разрешённых служб/контейнеров, PostgreSQL/HTTP readiness, TLS и ошибки только агрегатами без текста журналов/секретов. Каждая проверка получает работает/ошибка/нет данных и время измерения; TCP listener не выдаётся за доказательство VPN data path, getMe не доказывает обработку кнопок.

Notifier — отдельный непривилегированный процесс, токен только из защищённого файла, единственный разрешённый приватный owner chat. Проверки каждую минуту, полный отчёт каждые4часа, состояние уведомлений и курсор updates на диске, ограниченные повторы при Telegram/API errors. Нужны systemd hardening/autostart, backup/rollback и проверка реального sendMessage с Message ID; Telegram acceptance не доказывает прочтение человеком.

Для серверного доступа к метрикам второго VPS нельзя копировать административные приватные ключи Mac. Подготовить отдельный канал только чтения фиксированного sanitized snapshot, с минимальными правами, host-key pinning, резервной копией и откатом. Предусмотреть наблюдателя на втором существующем VPS, иначе смерть самого monitor-хоста останется без предупреждения. Одновременное отключение обоих VPS без внешнего наблюдателя не покрывается. Этот транспорт, collector/notifier и systemd пока не реализованы и не развёрнуты.

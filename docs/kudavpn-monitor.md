## Архитектура

Отдельный read-only collector, актуальные CPU/RAM/диск, состояние разрешённых служб/контейнеров, PostgreSQL/HTTP readiness, TLS и ошибки только агрегатами без текста журналов/секретов. Каждая проверка получает работает/ошибка/нет данных и время измерения; TCP listener не выдаётся за доказательство VPN data path, getMe не доказывает обработку кнопок.

Notifier — отдельный непривилегированный процесс, токен только из защищённого файла, единственный разрешённый приватный owner chat. Проверки каждую минуту, полный отчёт каждые4часа, состояние уведомлений и курсор updates на диске, ограниченные повторы при Telegram/API errors. Нужны systemd hardening/autostart, backup/rollback и проверка реального sendMessage с Message ID; Telegram acceptance не доказывает прочтение человеком.

Для серверного доступа к метрикам второго VPS нельзя копировать административные приватные ключи Mac. Нужен отдельный канал только чтения фиксированного sanitized snapshot, с минимальными правами, host-key pinning, резервной копией и откатом. Наблюдатель на втором существующем VPS необходим, иначе смерть самого monitor-хоста останется без предупреждения. Одновременное отключение обоих VPS без внешнего наблюдателя не покрывается. Подготовленная реализация описана ниже; до проверки установки не считать её развёрнутой.

## Код и порядок обновления

`monitor/collector.py`: отдельный read-only root collector для systemd/Docker, SELECT1 в read-only режиме, CPU/MemAvailable/диска, TCP, доверенного TLS и агрегированных ошибок. Персональная тестовая подписка проверяется только по уже существующему URL, полученному из nonce/HMAC через SELECT без issue/rotation/изменения БД. Ответ профиля не сохраняется. Ошибки журналов передаются только числом; старый failed-контроллер показывается отдельно без автоматического restart.

`monitor/worker.py`: непривилегированный owner-only notifier; первичный на JustHost и резервный на DO. Полный отчёт каждые4часа по UTC-границам, время в отчётах America/Los_Angeles. Срочные события после двух последовательных проб, одно уведомление на инцидент и восстановление; состояние и подтверждённые Telegram message IDs в SQLite0600. Перезапуск не дублирует уже подтверждённые части сообщения. Bot API не даёт exactly-once при потерянном ответе sendMessage: неопределённый исход имеет backoff, строгая гарантия невозможна.

Между VPS передаётся только фиксированный sanitized JSON: новые отдельные SSH-ключи с from-IP, restrict и forced command `/usr/bin/cat /var/lib/kudavpn-monitor-collector/export.json`. Административные ключи Mac не копируются. Изменение authorized_keys только добавляет ограниченный ключ, прежние строки сохраняются в закрытой резервной копии; откат удаляет только добавленную строку. Конфигурация SSH/sshd, приложений, VPN и БД не изменяется.

`deploy/monitor` содержит отдельные systemd units: collector.timer каждую минуту, worker с WatchdogSec180/Restart/автозапуском и отдельными каталогами. Root collector имеет ограниченные capabilities и read-only filesystem; Telegram-токен получает только непривилегированный notifier через systemd Credentials →0600 private state. Из-за systemd0440 staging обязательно, guard не ослабляется. Резервный наблюдатель предупреждает о потере primary heartbeat, а при пропуске полного отчёта более10мин отправляет резервный; startup grace180сек предотвращает ложный failover при установке. На обоих узлах недоступные данные не становятся зелёными.

Перед стартом: закрытые копии root authorized_keys и protected PID/container StartedAt; собственные новые конфигурации/секреты, строгие known_hosts из ранее доверенных ключей, проверка systemd units и снимков, проверка forced command, независимого административного входа, затем запуск DO watchdog и JustHost primary. При ошибке отключить только Monitor/collector и удалить только его ограниченные строки ключей; БД/приложения не откатывать. Реальная проверка доставки — полный отчёт и явно помеченный [ТЕСТ] без остановки сервисов. Круглосуточная работа не должна зависеть от Mac/Codex; одновременный отказ обоих VPS или Telegram не имеет третьего внешнего канала оповещения.

# Карта готовности KudaVPN к платному запуску

Статус локальной разработки на 15 октября 2026 года. Этот файл не разрешает
обновление production и не подтверждает работу VPN из России.

## Зависимости веток

`main` → `codex/premium-production-baseline` →
`codex/subscription-lifecycle` → `codex/happ-subscriptions` →
`codex/xray-access-automation` → `codex/vpn-path-diagnostics` (PR #2) →
`codex/commercial-readiness` (PR #3) → `codex/happ-link-delivery` (PR #4)
→ `codex/payment-admin-prep`.

`codex/ci-foundation` (PR #1) ответвляется отдельно от Premium baseline. Его
последний коммит не является предком PR #2/#3; часть CI изменений перенесена
отдельным коммитом. Поэтому перед слиянием требуется сравнить обе ветки по файлам,
а не считать их линейной цепочкой.

Новые PR являются черновиками. PR #2 и #3 содержат изменения нижележащих
локальных веток; последовательность слияния нужно сверить по Git перед каждым
merge. `main` остаётся старой рабочей версией, а Docker на DigitalOcean не получает
код из PR автоматически. Не выполнять `git merge`, `docker compose up` или
миграции на production только по факту зелёного CI.

## Пользовательский путь

| Шаг | Состояние | Проверка и ограничение |
| --- | --- | --- |
| `/start`, профиль, меню и тарифы | Есть | Aiogram + тесты навигации, один редактируемый экран; работающий бот использует прежний релиз |
| Создание заказа | Частично | Локальный orchestration-слой с ключом идемпотентности и проверкой адреса оплаты; кнопка и реальный шлюз не подключены |
| Оплата YooKassa/СБП | Нет в production | Офлайн-обработчик повторных статусов через независимый lookup; HTTP-адаптер, webhook и доступность СБП конкретному магазину неизвестны |
| Активация, продление, истечение | Есть локально | PostgreSQL-тесты в CI, без боевого платежа и развёртывания |
| Персональная ссылка Happ | Есть локально при опциональной настройке | Выдача только владельцу с активной оплаченной подпиской и живым узлом; HTTPS ingress и ключ вне Git ещё не созданы |
| Много узлов, отзыв доступа | Есть локально | Агент Xray, mTLS, короткие аренды и обновляемый список; реальная проверка каждого узла из России обязательна |
| Android Happ без другого VPN | Не подтверждено | Прежние DigitalOcean/JustHost тесты не дали рабочего трафика; ждать проверенного маршрута |
| Администрирование | Частично | Локальный read-only обзор агрегатов с отказом для остальных ID; API/UI, управление, роли и журнал действий отсутствуют |

## Проверки перед разрешением продаж

1. Отдельный тестовый VPN-узел: проверить TCP, REALITY/VLESS, DNS и HTTPS
   непосредственно из домашнего Wi-Fi в России и импорт Happ на Android.
   Контрольный сценарий должен отличать недоступность сети от ошибки Xray.
2. На копии базы применить миграции до `head`, сверить пользователей, подписки,
   историю и активные экраны, затем проверить восстановление резервной копии.
3. Выделить HTTPS-домен подписки с TLS и защитой URL-токенов в access-log,
   reverse proxy и мониторинге. Закрыть API узлов mTLS, ограничить роли БД,
   проверить краткосрочное истечение аренды на отключённом центральном сервере.
4. Подготовить тестовый магазин YooKassa и проверяемый серверный GET платежа.
   Тесты: успех, отмена, дубликат webhook, сбой сети, неверная сумма/владелец,
   возврат и гонка продления. До этого бот не показывает кнопку оплаты.
5. Добавить административный интерфейс с явными ролями, журналом изменений и
   ограничениями на массовые операции. Проверить отказ доступа обычному клиенту.
6. Выпустить пакет релиза и план отката, сохранить текущий image ID. На сервере
   выполнить backup и restore на отдельную БД, миграцию и smoke до переключения.
   Запускать один polling; новый код без отдельного разрешения не выкатывать.

## Конфигурация и откат

Необходимые для существующего бота переменные перечислены в `.env.example`:
`BOT_TOKEN`, `DATABASE_URL`, `DATABASE_URL_DOCKER`, `POSTGRES_*`. Для локальной
опциональной выдачи Happ нужны `SUBSCRIPTION_PUBLIC_URL` и 32-байтный
`HAPP_LINK_SECRET` в base64url без padding. Его нельзя хранить в Git/образе;
сохранить отдельно от резервной копии БД. API подписок требует TLS-сертификат,
ключ и закрытый `NODE_AGENT_CONFIG`. Без этих опций бот сохраняет прежний экран,
а платежи остаются выключенными.

Для будущего Veesp-узла: сперва проверка IP/маршрута из РФ, затем отдельный Xray
и закрытый агент с собственными ключами; публичные REALITY-поля добавить в
`vpn_nodes` только после теста. Включение узла в списке требует успешного mTLS
health, настроенного доступа и действующей аренды; старые ссылки обновятся без
перевыпуска. Не копировать секреты DigitalOcean/JustHost.

Существующие процедуры backup, сверки и отката описаны в
[`docs/production.md`](production.md) и [`docs/cutover.md`](cutover.md). Откат
релиза: прекратить только новый polling, проверить его завершение, сохранить
свежую БД, вернуть прошлый image, если прежний код совместим с новой схемой.
Откат БД из старого dump без анализа новых записей запрещён. Для нового сервиса
подписок достаточно остановить только его; Telegram и PostgreSQL не трогать.

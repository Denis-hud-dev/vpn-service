# Компактный стартовый экран — 28 октября 2026

PR29 продолжен поверх b2ec06a. Изменения только приветствия/навигации тестового бота; НПД, платежи, каталог, выдача профилей и веб-сайт не меняются.

## Поведение

Первый `/start`: существующий ledger фиксирует первый вход, устанавливается прежняя постоянная ReplyKeyboard, отправляется оригинальный `bot/assets/welcome-premium.png`, сразу следом — управляемый текстовый экран с актуальным snapshot подписки. Дополнительного «Начать пользоваться» больше нет. Исторические кнопки `pilot:begin` остаются совместимыми.

Главный экран: KudaVPN Premium / «Свобода начинается здесь», три короткие строки преимуществ, реальный статус и UTC-срок активной подписки. Просроченный snapshot active отображается как истёкший; недоступные данные не выдаются за активный доступ. UUID, персональные URL и конфигурации отсутствуют.

Клавиатура:

- отдельная основная строка: «💎 Купить VPN»;
- «👤 Моя подписка» | «🚀 Подключиться»;
- «💬 Поддержка» | «ℹ️ Информация».

«Купить VPN» открывает существующий информационный каталог199/499/1790, квартал «Рекомендуем». Заказ/внешняя checkout-ссылка/Stars в боте не создаются. Оплата остаётся самостоятельным сценарием сайта. Подписка, поддержка и Happ используют существующие обработчики; новый nav:info открывает прежний экран информации. Канал/чат не создаются, вымышленных ссылок нет.

Повторный `/start` обновляет snapshot и актуальный экран, восстанавливает нижнюю клавиатуру, не повторяет баннер. Обычные сообщения и `/start` владельца не удаляются этой новой логикой; прежний механизм очистки распознанных нижних навигационных команд сохранён. Финансовые уведомления и баннер не входят в навигационный указатель и сохраняются. При недоступной SQLite ledger (EROFS) навигация остаётся работоспособной.

## Проверки

86 профильных тестов прошли, ещё2 новых регрессии прошли в целевом наборе15 (всего88 различных профильных проверок). Покрыты новый/существующий пользователь, первый/повторный start, реальное изменение snapshot, истёкшая/заблокированная/отсутствующая подписка, ошибка чтения, пять кнопок, каталог и отсутствие создания оплаты, legacy begin, ReplyKeyboard, важные уведомления, отказ Telegram при edit/delete, восстановление после перезапуска, fallback custom emoji/стилей. Состояние первого входа проверяется на изолированных fixtures, без сброса аккаунта владельца или финансовых данных.

Telegram сам определяет тему, размеры и вид кнопок. Используется штатный primary-акцент и уже опубликованный пакет custom emoji; недоступные emoji/стили имеют прежний fallback. Нет произвольного цвета фона сообщений. Физические Android/iOS требуют проверки владельцем.

## Безопасное развёртывание

Предварительно read-only подтверждены active/ready тестового бота, его cwd0d45896, pilot welcome/premium флаги и отдельный UID. Сайт/bridge/feed active. `update_menu.py` жёстко ожидает этот runtime и сохраняет конфиги, drop-ins, canonical dump и отдельную SQLite ledger. Копирует текущий runtime и заменяет только5 reviewed UI-файлов: screens, keyboards/main, premium_emoji, handlers/start, navigation. Существующие публичные сигнатуры неизменны; допускается только новый information callback. Все остальные байты (включая backend/main/config/миграции/НПД) должны совпадать с прежним runtime.

Откат возвращает предыдущий98-purchase-menu.conf и перезапускает только TEST-бота. Проверяются readiness, неизменность финансовых/profile данных и защищённых служб/конфигов/портов, включая сайт и Monitor. Состояние БД из дампа автоматически поверх новых событий не восстанавливается. Итог CI и реальный rollout записываются после выполнения.
